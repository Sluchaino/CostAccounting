# CashFlow — учёт финансов на Android

Нативное приложение **на Kotlin** для телефона с Android 8.0 и новее. Работает полностью без интернета: интерфейс построен из Android Views, данные хранятся в SQLite во внутренней памяти приложения. В манифесте нет разрешения `INTERNET`. Сервер, браузер, PostgreSQL, Docker и установка Java на телефон не нужны.

## Установка на телефон

[Скачать готовый APK 1.4.1](apk/CostAccounting-Android.apk?raw=true). Перенесите его на телефон, откройте и подтвердите установку. Это отладочная сборка, подписанная ключом разработки; она предназначена для непосредственной установки и проверки, а не для публикации в Google Play. Для обновления поверх установленного приложения нужна подпись тем же ключом. Локальная сборка также доступна в `dist/CostAccounting-Android.apk`.

## Возможности

- Обзор: баланс, доходы, расходы и последние операции.
- Операции: добавление, редактирование, удаление, выбор даты и времени, комментарии.
- Составные покупки: одна общая сумма и несколько категорий расходов; распределение можно заполнить сразу или позже. Нераспределённый остаток учитывается отдельно.
- Фильтры по периоду, категории и типу операции; даты учитывают часовой пояс телефона.
- Категории доходов и расходов. Категорию с операциями нельзя удалить. Изменение её типа пересчитывает отчёты по связанным операциям.
- Отчёты: итоги за период и распределение по категориям с долями.
- Общая круговая диаграмма категорий с переключением «Всё / Расходы / Доходы». При исключении типа операций диаграмма и проценты пересчитываются без пересоздания страницы. Нажмите сектор или строку легенды для подробностей.
- План: регулярные доходы и расходы каждый месяц или каждый год, изменение суммы, пауза и удаление расписания.
- Прогноз доходов и расходов на текущий и следующие 12 месяцев, с детализацией и ожидаемым итогом месяца.
- Резервные копии в JSON через системный выбор файла. Восстановление проверяет файл, запрашивает подтверждение и заменяет данные одной транзакцией.

Все суммы хранятся целым числом копеек; расчёты не используют `Double`. Приложение не требует регистрации, внешних шрифтов или сетевых сервисов. При первом запуске добавляются категории «Еда», «Транспорт», «Подписки», «Развлечения» и «Зарплата».

## Суммы и оформление

Сумма вводится одним полем через запятую, например `1 250,45 ₽`. Цифровая клавиатура поддерживает дробную часть; введённая точка автоматически отображается как запятая. Внутри хранится точное количество копеек. Все суммы, включая баланс, прогноз и подписи диаграмм, отображаются с двумя знаками после запятой.

Версия 1.2 обновляет оформление карточек, навигацию с векторными значками, поля ввода и типографику. Длинные суммы уменьшают размер шрифта, чтобы дробная часть оставалась видна. Диаграммы рисуются штатным Canvas без сетевых ресурсов или постоянной анимации. Изменение оформления не изменяет существующую базу данных.

## Область будущего баннера

Над нижним меню на всех вкладках зарезервирован отдельный контейнер `BannerSlot`: ширина 100% доступной области экрана, высота ровно 50 dp и отступ 6 dp до меню. Он находится вне прокрутки страницы и занимает собственное место в вертикальной разметке, поэтому контент и кнопки не перекрываются. Системные отступы учитываются внешним контейнером.

Рекламный SDK пока не подключён; область остаётся пустой. Для будущей интеграции после измерения контейнера используйте `BannerAdSize.fixed(context, bannerSlot.availableWidthDp, BannerSlot.HEIGHT_DP)` и пересчитывайте размер при изменении ширины окна. Ширина берётся из фактически измеренной области с переводом физических пикселей в dp. Контейнер сохраняется при обновлении страницы и переключении вкладок.

## Составные покупки

При добавлении операции включите «Составная покупка», укажите общую стоимость и выберите от 2 до 50 категорий расходов. Название покупки необязательно. Поля сумм категорий можно оставить пустыми, сохранить покупку и позднее открыть её карточку для распределения. Заполненные суммы не должны превышать общую стоимость; остаток виден как «Не распределено» в карточке и диаграмме.

В списке это одна покупка; в общих итогах её стоимость учитывается один раз. В фильтре категории показываются покупки, в которых она выбрана, а сумма итогов отражает только её долю; карточка показывает полную стоимость покупки. Смена типа категории, используемой в составной покупке, блокируется, пока не изменено распределение.

Версия 1.4 обновляет базу с версии 2 до 3 с сохранением операций и расписаний. Новые резервные копии формата 3 хранят распределения; прежние форматы 1 и 2 продолжают импортироваться. Фильтры категорий/типов, выбор нескольких категорий и подтверждения используют общие стили диалогов и форм.

## Регулярные платежи

Версия 1.3 сохраняет положение прокрутки при обновлениях страницы. Кнопки месяца обновляют только значения внутри блока прогноза — экран и диаграммы не создаются заново. Формы операций, категорий и расписаний используют единые поля, списки выбора, подписи и ошибки. Комментарий многострочный, со счётчиком символов; кнопки действий остаются за пределами прокручиваемой части формы.

Откройте вкладку «План», задайте название, сумму, категорию (доход или расход), первую дату и повторение «Каждый месяц» или «Каждый год». При открытии приложения или возвращении в него наступившие даты автоматически добавляются в историю. Фоновый сервис и постоянно работающий процесс не нужны. Если приложение было закрыто несколько месяцев, пропущенные платежи будут добавлены при следующем открытии.

Расписание сохраняет исходное число: 31 января → 28/29 февраля → 31 марта. Ежегодный платёж от 29 февраля приходится на 28 февраля в невисокосный год и снова на 29 февраля в високосный.

Создание расписания с прошедшей первой датой добавляет наступившие платежи. Изменение суммы и категории действует на ещё не созданные операции. Смена первой даты или периодичности начинает новый расчёт с сегодняшнего дня. После возобновления паузы пропущенные во время паузы периоды не начисляются. Удаление расписания сохраняет уже созданные операции; удалённая из истории операция не появится повторно при следующем открытии.

## Прогноз доходов и расходов

В обзоре показаны ожидаемые доходы и расходы к концу текущего месяца. В отчётах один общий график показывает доходы и расходы выбранного месяца на единой шкале, а под ним — итог месяца (доходы минус расходы). Кнопки месяца обновляют существующий график без пересоздания страницы и сброса прокрутки. Подробности открываются кнопкой «Показать расчёт». Расходы рассчитываются как фактические расходы + уже внесённые будущие операции + предстоящие регулярные расходы + оценка остальных трат.

Для оценки обычных трат используется средний дневной расход за доступную историю до вчерашнего дня, максимум за 90 дней. Автоматически созданные регулярные операции и доходы из этой базы исключаются. Требуется не менее 7 дней истории; при меньшей истории учитываются только фактические и известные будущие расходы. Уже внесённые будущие обычные расходы уменьшают оставшуюся оценку, чтобы не учитывать их дважды. Прогноз — ориентир по вашим данным, а не гарантированная сумма. Старые обычные операции автоматически не распознаются как регулярные.

Доходы прогнозируются по завершённым месяцам, а не по дневной ставке: разовая зарплата не умножается на оставшиеся дни. Учитываются полученные суммы, будущие операции и регулярные доходы. Дополнительные поступления оцениваются по среднему обычному доходу каждой категории за доступные завершённые месяцы, максимум за 3, за вычетом уже учтённых поступлений этой категории. Автоматически созданные регулярные доходы исключены из истории для оценки. При отсутствии завершённого месяца учитываются только фактические и известные будущие доходы.

## Хранение данных

База `cashflow.db` хранится в приватной папке приложения и сохраняется после закрытия и перезапуска. Автоматическое облачное резервирование отключено. Удаление приложения удалит его базу: заранее сохраните JSON-копию кнопкой «Сохранить копию в файл» на экране обзора. Для полностью автономной копии выберите локальную папку телефона или SD-карту в системном диалоге. Копия содержит финансовые данные, храните её в подходящем месте.

Обновление до версии 1.4 переводит схему базы с версии 1 или 2 на версию 3 без удаления данных. Новые JSON-копии формата 3 включают составные покупки, расписания и их состояние; форматы 1 и 2 также поддерживаются при восстановлении.

## Разработка и сборка

Откройте корень проекта в Android Studio. Требуются JDK 17–24 (проверено на JDK 21), Android SDK Platform 36, Build Tools 35.0.0+ и Gradle 8.14.3 через включённый Wrapper. Путь к SDK задаётся Android Studio в игнорируемом `local.properties` либо переменной `ANDROID_HOME`. Интернет нужен только при первоначальной подготовке зависимостей сборки; готовое приложение полностью автономно.

Windows:

```powershell
.\build.ps1
```

Linux/macOS:

```sh
sh build.sh
```

Скрипт выполняет модульные тесты, Android Lint и сборку APK, затем копирует результат в `dist/CostAccounting-Android.apk`. По умолчанию используется один рабочий процесс Gradle, ограниченная память и компилятор Kotlin внутри процесса сборки. Эмулятор автоматически не запускается.

Дополнительная проверка SQL-миграции без эмулятора: `python scripts/test_migration.py` (стандартная библиотека Python, дополнительные пакеты не нужны).

Проверки базы SQLite, резервных копий и разрешений на устройстве/эмуляторе:

```sh
sh ./gradlew connectedDebugAndroidTest
```

В Windows используйте `gradlew.bat`. Тесты базы используют отдельные временные базы и не очищают пользовательскую базу приложения. Для установки по USB: `adb install -r dist/CostAccounting-Android.apk`.

Основные файлы: `MainActivity.kt` — нативные экраны и формы; `Ledger.kt` — денежные расчёты и отчёты; `LedgerDatabase.kt` — SQLite; `Backup.kt` — локальные копии. Исходная веб-версия доступна в истории Git. Windows-версия из предыдущей итерации заменена Android-приложением.
